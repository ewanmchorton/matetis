# Архитектура МАТЕТИС

Принято 13 октября 2026. Это решение для разработки полноценного приложения. Прототип остаётся на Next.js: экраны не переписываем, меняется только место хранения данных.

Не предлагай другой хостинг, базу или хранилище файлов без явной просьбы.

## Что используем

| Задача | Сервис |
|---|---|
| Сайт и PWA | Cloudflare |
| Вход, регистрация и база | Supabase, регион Франкфурт (`eu-central-1`) |
| Изображения, PDF и книги | Cloudflare R2 |
| Видео | Внешний видеохостинг, не наше хранилище |

База — PostgreSQL. Правила доступа к чужим данным живут в базе, а не только на экране. Дата рождения, тип человека и расчёт по дате рождения другим пользователям не показываются.

## Три обязательных уточнения

1. **Своя почта для писем.** Для регистрации реальных пользователей нужен собственный SMTP-сервис. Стандартная почта Supabase отправляет 2 письма в час. Этого хватает только на проверку одним человеком, не на тестовую группу.
2. **Бесплатный Supabase может уснуть.** Проект на бесплатном плане могут приостановить при низкой активности в течение 7 дней. Это не правило «если никто не заходил каждый день». Перед паузой Supabase присылает предупреждение. Данные при этом не удаляют, проект можно включить обратно из кабинета.
3. **До запуска тестовой группы.** Предусмотрим резервное копирование базы и проверку, что приложение открывается из Беларуси и России без VPN. На бесплатном плане автоматических копий нет, поэтому копии нужны отдельно, до того как группой начнут пользоваться.

## Что пока не делаем

- Не храним видео в R2 и не в хранилище Supabase.
- Не переносим приложение на серверную оболочку Cloudflare. Сайт остаётся клиентским PWA, как текущий прототип. Данные и вход идут в Supabase.
- Не переносим приложение на отдельный сервер в России, пока проверка из России без VPN не покажет, что Cloudflare или Supabase оттуда не открываются.
- Не включаем платный Supabase, пока нет тестовой группы, которой нельзя остаться без приложения. На время разработки бесплатного плана достаточно, с оговорками выше.

## Ближайший шаг разработки

Порядок этапов — в [`docs/plan.md`](plan.md). Карточка человека в базе входит в этап «Вход и регистрация»: [`docs/tasks/01-person-card.md`](tasks/01-person-card.md).

Почта и пароль уже хранятся механизмом входа Supabase. Имя, согласие на обработку данных и признак администратора должны лежать в отдельной таблице `public.profiles` до того, как регистрация в приложении начнёт их сохранять. Дата рождения, тип, практики и друзья в эту таблицу не входят: для создания учётной записи они не нужны.

## Для кого

Сначала Беларусь. Франкфурт для этого подходит: Германия входит в перечень стран с надлежащей защитой персональных данных. Россия — возможная аудитория, не отдельная копия приложения. Требование хранить данные граждан России внутри России в эту версию не входит. Если проверка без VPN из России не пройдёт, это отдельное решение, а не повод заранее заводить второй сервер.
