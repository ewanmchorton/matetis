# Задание: база, вход и карточка человека

Открой этот текст в отдельном чате и выполни только его. Архитектура — в `docs/architecture.md`, данные — в `docs/data-model.md`. Экраны приложения не меняй.

## Зачем это сейчас

Все следующие таблицы (тест, практики, отметки, друзья) ссылаются на человека. Пока нет базы и учётной записи с именем, согласием и ролью, сохранять что-либо за человеком некуда.

## Результат

На компьютере разработчика одной командой запускается база PostgreSQL в Docker. В базе есть учётные записи Better Auth и карточка человека. Регистрация через сервер создаёт человека с именем, временем согласия и ролью `user`. Экраны прототипа работают как раньше.

## Что сделать

1. **Подготовка компьютера.** Проверь, установлены ли Docker (или OrbStack) и pnpm. Если нет — дай человеку пошаговую инструкцию по установке и дождись, пока он закончит.
2. **`docker-compose.yml`:**
   - PostgreSQL с данными в именованном вольюме;
   - локальный почтовый ящик (Mailpit) для писем входа.
   Приложение в Docker пока не упаковывай.
3. **Настройки.** Файл `.env.example` с примером всех настроек без настоящих паролей. Настоящие значения — в `.env.local`, он в Git не попадает.
4. **Drizzle.** Подключить, описать таблицы в коде, изменения базы — файлами-миграциями в Git. Команды для применения миграций — в `package.json`.
5. **Better Auth.** Вход по почте и паролю, учётные записи в нашей базе.
6. **Карточка человека** — поля по разделу «Человек и вход» в `docs/data-model.md`:

   | Поле | Смысл |
   |---|---|
   | Имя | Вводится при регистрации, пустым не бывает |
   | Роль | `user` или `admin`. У нового человека всегда `user` |
   | Время согласия на обработку данных | Момент согласия при регистрации |
   | Когда создана и когда изменена | Служебные отметки времени |

   Аватар и дату последней активности пока не добавлять.
7. **Правила:**
   - Роль нельзя передать при регистрации и нельзя сменить запросом от человека. Админа назначает только команда на сервере или запрос в базу.
   - Регистрация без согласия на обработку данных не проходит.
   - Почта и пароль хранятся только в таблицах Better Auth. Пароль — только в зашифрованном виде.

## Что проверить

1. `docker compose up` запускает базу, миграции применяются без ошибок.
2. Две проверочные регистрации дают двух человек с ролью `user`, именем и временем согласия.
3. Регистрация с полем роли `admin` всё равно создаёт `user`.
4. Регистрация без имени или без согласия отклоняется.
5. После перезапуска контейнера данные на месте.
6. В Git нет файлов с паролями и секретами.
7. Проходят `pnpm typecheck`, `pnpm lint`, `pnpm build`. Экраны прототипа открываются, как раньше.
8. Если серверная часть ломает публикацию прототипа на GitHub Pages — остановись и спроси, что делать, а не отключай её молча.

## Не делать в этом задании

- Не менять экраны и не подключать к ним вход.
- Не арендовать сервер и не подключать сервис рассылок.
- Не добавлять таблицы теста, практик, отметок и друзей.
- Не упаковывать приложение в Docker и не настраивать копии базы.
