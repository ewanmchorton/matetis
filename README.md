# МАТЭТИС

Название в коде: `APP_NAME` в `src/shared/config/brand.ts`.

Веб-приложение для телефона (PWA): тест определяет один из 12 психотипов, дальше – программа практик
под связку «тип + текущая стихия» (даосская пятёрка). Сервер Next.js, база PostgreSQL – `docs/architecture.md`.

**Первый вход:** вход по коду из письма или через Telegram → онбординг → тест → результат.

**Вкладки** (только с доступом):

- **Программа** – практики утра и вечера, на неделю и на стихию, навигатор дня, спутник «Гармония»
- **Вместе** – совместная практика с другом, предложение месяца, лента событий друзей
- **Библиотека** – стихии, редкие практики, книги в читалке
- **Профиль** – спутник, друзья, тип, журнал, фраза дня, дата рождения

**Админка** – `/admin`, вход по почте и паролю:

- **Стихии** – текущая стихия, день перехода на Металл, картинки стихий
- **Навигатор** – послания Мастеров: три части с заданиями, типы, порядок
- **Практики** – ежедневные (утро и вечер), еженедельные, осознания, фразы дня
- **Библиотека** – видео стихий, редкие практики, книги и обложки
- **Матэтисы** (только админ) – все люди: доступы и оплаты, тип и стихии, роль в команде и пароль

На GitHub Pages публикуется копия экранов с примерами, без сервера.
Меню **«Экраны»** сверху справа – быстрый переход между экранами при разработке.

## Как запустить

Node.js 20+ и pnpm.

```bash
pnpm install
pnpm dev          # http://localhost:4317
```

- `pnpm typecheck` · `pnpm lint` · `pnpm build`
- `pnpm test` – автоматические тесты правил. Работают с отдельной базой `matetis_test`, нужна запущенная база (`pnpm db:up`)

## База и вход (локально)

Нужен Docker (на Mac – OrbStack).

```bash
cp .env.example .env.local   # затем впишите BETTER_AUTH_SECRET: openssl rand -base64 32
pnpm db:up                   # база PostgreSQL и почтовый ящик Mailpit (http://localhost:8025)
pnpm db:migrate              # применить миграции из папки drizzle/
```

- Таблицы описаны в `src/shared/db/schema/`. После их изменения: `pnpm db:generate`, затем `pnpm db:migrate`.
- Вход и регистрация – Better Auth, адрес `/api/auth/*`, настройки в `src/shared/auth/server.ts`.
- Назначить администратора (человек должен быть уже зарегистрирован): `pnpm admin:promote <email>`.
  Команде нужен доступ к базе (`DATABASE_URL`), из приложения роль сменить нельзя.
- Создать двух тестовых людей, которые дружат: `pnpm db:seed-friends`.
- Создать тестового администратора, а Анне Тестовой добавить тест и дату рождения: `pnpm db:seed-admin`. Почта и пароль для входа в админку – в `scripts/seed-admin.mts`.
- Вход в админку – `/admin/login`, по почте и паролю. Пароль первому администратору: `pnpm admin:set-password <email>`. Остальным роль и пароль назначает администратор в карточке человека в разделе «Матэтисы».
  Страницы админки проверяет `requireAdminPage()` из `src/shared/auth/session.ts`, запросы – `assertStaff` и `assertAdmin` в серверных функциях.
- Тестовые данные: `pnpm db:seed-program` (программа), `pnpm db:seed-together` (Вера и Глеб для «Вместе»), `pnpm db:seed-journal` (журнал).
- Вход через Telegram: заполните `TELEGRAM_*` в `.env.local` (см. `.env.example`) и рядом с `pnpm dev`
  запустите `pnpm telegram:dev` – команда пересылает сообщения боту в приложение на компьютере.
  На сервере вместо неё Telegram сам присылает сообщения на `/api/telegram/webhook` (настраивается при публикации).

## Сервер

Всё для сервера – в папке `deploy/`: приложение (образ из `Dockerfile`), база и Caddy с HTTPS.

```bash
cd deploy
cp .env.example .env   # вписать пароли и ключи; для проверки на компьютере DOMAIN=localhost
docker compose up -d --build
```

- При запуске приложение само применяет новые миграции из `drizzle/`. Не получилось – приложение останавливается, причина в `docker compose logs app`.
- Загруженные в админке файлы лежат в вольюме `files` (внутри контейнера – `/app/private`), база – в вольюме `db-data`.
- На компьютере Caddy выдаёт свой сертификат для `localhost`, браузер предупредит о нём – это нормально. Письма уходят в Mailpit, если в `.env` указать `SMTP_HOST=host.docker.internal`, `SMTP_PORT=1025`, `SMTP_SECURE=false`.

## Структура (FSD)

```
src/
  app/          маршруты Next.js: (mobile)/ – экраны в рамке телефона, admin/ – веб-админка
  views/        экраны
  widgets/      нижнее меню, рамка телефона, оболочка админки, навигация по прототипу
  features/     прохождение теста, редакторы админки, уведомления, установка приложения
  entities/     данные и правила: *.server.ts – только сервер, остальное – экраны
  shared/       база, вход, UI, маршруты, утилиты
```

Примеры для сайта без сервера лежат рядом с экранами (`demo…` в `views/*/api`). Правила для агентов – [`AGENTS.md`](./AGENTS.md).
